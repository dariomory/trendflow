# 0.2.0

Reaches feature parity with [trendflow-js](https://github.com/dariomory/trendflow-js) 0.1.0
for trending searches and proxy handling.

## Fixed

- **`trending_now()` works again.** Google retired the
  `hottrends/visualize/internal/data` endpoint it called, along with `api/dailytrends` and
  `api/realtimetrends`; all three return HTTP 404, so every call had been failing. It now
  runs on the `batchexecute` RPC that trends.google.com itself uses, which needs no cookie
  and answers on IPs the widgetdata endpoints reject.
- **Spurious HTTP 429s.** Google refuses requests carrying a default Python HTTP client
  User-Agent regardless of request volume. A browser User-Agent is now sent by default,
  which is what made "rate limits" appear on a first request.
- **Proxies no longer rotate mid-query.** The transport used to advance the proxy after
  every successful request and re-fetch the `NID` cookie each time. That cannot work against
  Trends: Google binds the cookie and the widget token to the IP that requested them, so a
  query whose follow-up call left from a different exit IP was answered with a 429.

## Added

- **Proxy pool.** `Client(proxies=[...])` rotates through a list of proxy URLs from any mix
  of providers, advancing on 429, 403, and network errors and re-seeding the cookie jar each
  time. `max_proxy_attempts` caps the retries, `on_proxy_rotate` reports them, and
  `current_proxy` exposes the pinned proxy. Rotation is per query, never per request.
- **Richer trending data.** `TrendingItem` gains `growth` (percentage rise) and `volume`
  (relative search volume); `traffic` is now the formatted growth, e.g. `"+3,950%"`.
- **`trending_now()` accepts any country code** rather than 16 hardcoded names, and defaults
  to worldwide instead of raising.
- `window=TRENDING_WINDOW_TOP` selects highest-volume searches instead of fastest-growing.
- `geo_list()` returns Google's full region hierarchy.
- `UnknownRpcError` is raised when Google renames a `batchexecute` RPC id, instead of
  silently returning nothing. Pass `rpc_ids` to patch without waiting for a release.

## Changed

- `TrendingItem.articles` is always empty: the replacement endpoint carries no article
  links. The field is kept for compatibility.
- `TRENDING_PN` is gone, replaced by direct country codes.

## Notes

The same `batchexecute` endpoint exposes a higher-precision timeseries and keyword-scoped
related queries, but both require a reCAPTCHA Enterprise token and are deliberately not
implemented. That data remains available through `interest_over_time()` and
`related_queries()`.
